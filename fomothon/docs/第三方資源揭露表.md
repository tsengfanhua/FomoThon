## 3. 模型與外部 API

| 資源 | 用途 | 使用時機 | 送出的資料 |
| --- | --- | --- | --- |
| OpenAI `gpt-4.1` | 比賽簡章 → 參賽條件與技能需求；相近技能的逐對判斷 | 建立資料（`scripts/setup_hub.sh --analyze`）與從網頁觸發的分析 | 公開的比賽簡章；ESCO 技能名稱與說明 |
| OpenAI `gpt-4.1-mini` | 教師 profile → 技能；課綱 → 技能；技能的中文名稱 | 同上 | 教師的專長條列與論文、計畫標題；課綱文字；ESCO 技能名稱 |
| OpenAI `text-embedding-3-small` | 找語意相近技能的候選 | 同上 | ESCO 技能名稱與說明 |
| OpenAI `gpt-5-mini` | 開發期間比較兩種技能抽取寫法，結果記錄在 `*/docs/skill_extraction_comparison.json` | 只用於這次比較 | 合成課程的課綱文字 |
| 競賽 Agent 的選用抽取器（`competition-agent/src/competition_agent/skills/`） | 另一條比賽技能抽取流程 | 預設關閉；開啟時要另外設定模型、請求上限與預算 | 公開的比賽文字 |
| Claude Opus 5.5／Sonnet 5.5／Haiku 5.5（Anthropic API） | 網站助理的任務辨識、課綱語意萃取、在合法清單內選下一步、說明潤飾；依 `fomothon/config/models.json` 的路由分流 | 選用，預設關閉（`FOMO_LLM_PROVIDER=none`）；評測與 Demo 影片都在關閉狀態下執行 | 送出前遮蔽個資、人名代號化；輸出都經檢核，計分與資格由規則決定 |
| OpenAI 相容端點、Gemini 相容端點、校內地端模型 | 網站助理的替代路由 | 選用；`config/models.json` 中的範例設定 | 同上 |
| ESCO API | 建置網站 Skill 指標庫時查詢 43 項技能的 URI | 只在開發時使用一次，系統執行時不呼叫 | 技能名稱 |

金鑰只從環境變數讀取（`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`），不寫在程式碼或設定檔裡。送給 OpenAI 的內容不含學生成績、學生身分、教師姓名與學經歷。網站執行時預設不呼叫外部模型，只有建立資料與從網頁觸發分析時才會呼叫。

## 4. 生成式 AI 的使用（開發與製作）

| 項目 | 工具 | 說明 |
| --- | --- | --- |
| 程式、測試與文件 | Claude Code（Anthropic Claude 模型）、GitHub Copilot | 協助撰寫程式、測試、評測程式、種子資料與文件。`fomothon/` 的初版由 Claude Code 依團隊 11/10 的架構討論與技能編碼標準產生 |
| 人為部分 | — | 團隊負責需求與架構、資料取得、判斷準則與驗收；AI 產出的程式與文件經團隊審閱、修改後才採用。驗證方式：自動化測試（網站 201 項，三個 Agent 與共用模組各自的 pytest）、評測腳本（`fomothon/eval/`）、匿名檢查（`npm run check:anon`） |
| 評測的標準答案 | 兩個不同的 AI 模型 | 課綱技能萃取的標準答案（`fomothon/eval/gold/annotations/`）由兩個 AI 模型各自標註、彼此看不到對方的結果，再取共識；不是人工標註 |
| 簡報與評測文件 | Claude | 協助撰寫文字與排版；數字都對照過實際執行結果 |
| Demo 影片 | Claude；MediaTek Breeze2-VITS；SenseVoice Small（經 sherpa-onnx） | 畫面以 Playwright 錄製實際系統操作。字幕與旁白稿由 Claude 協助撰寫；旁白以 Breeze2-VITS 在本機合成，再以 SenseVoice 在本機辨識，確認每一句都唸清楚。兩個模型都在本機執行，沒有把內容送到外部服務。授權：Breeze2-VITS 依 MediaTek Research 發布頁的條款；SenseVoice Small 依 FunASR Model License v1.1；sherpa-onnx 為 Apache-2.0 |
